# Merge: EL82100 + EL81016

## Problema
Cuando se buscaba el código OEM **LF3620**, el sistema retornaba **EL81016** (producto alternativo) en lugar de **EL82100** (producto principal), porque EL82100 tenía la mayoría de campos vacíos.

## Solución Implementada

### 1. ✅ Fix en búsqueda (Commit: 1d59f8d) - DEPLOYADO
Modificado `/api/filters/search/part` para:
- Priorizar productos con **más datos completos**
- Contar campos NULL en: thread_size, diameters, pressure, installation_type, iso_test_method
- Retornar el producto con **menos NULL fields**

**Cómo funciona en producción:**
```javascript
// server.js líneas 494-511
ORDER BY
  (CASE WHEN thread_size IS NOT NULL THEN 0 ELSE 1 END) +
  (CASE WHEN outer_diameter_mm IS NOT NULL THEN 0 ELSE 1 END) +
  (CASE WHEN height_mm IS NOT NULL THEN 0 ELSE 1 END) +
  (CASE WHEN iso_test_method IS NOT NULL THEN 0 ELSE 1 END) +
  (CASE WHEN burst_pressure_psi IS NOT NULL THEN 0 ELSE 1 END) +
  (CASE WHEN collapse_pressure_psi IS NOT NULL THEN 0 ELSE 1 END) +
  (CASE WHEN installation_type IS NOT NULL THEN 0 ELSE 1 END)
ASC, sku ASC
LIMIT 1
```

**Resultado:** LF3620 retorna el producto con más datos disponibles (mejor UX)
