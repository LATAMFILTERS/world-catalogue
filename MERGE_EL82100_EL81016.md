# Merge: EL82100 + EL81016

## Problema
Cuando se buscaba el código OEM **LF3620**, el sistema retornaba **EL81016** (producto alternativo) en lugar de **EL82100** (producto principal), porque EL82100 tenía la mayoría de campos vacíos.

## Solución Implementada

### 1. Fix en búsqueda (Commit: 1d59f8d)
Modificado `/api/filters/search/part` para:
- Priorizar productos con **más datos completos**
- Contar campos NULL en: thread_size, diameters, pressure, installation_type, iso_test_method
- Retornar el producto con **menos NULL fields**
- Resultado: Devuelve EL81016 si tiene más datos, pero marcado como alternativa

### 2. Merge de Datos (Este commit)
Ejecutada SQL para **mergear EL81016 → EL82100**:

```sql
UPDATE elimfilters_catalog SET
  iso_test_method = COALESCE(iso_test_method, (SELECT iso_test_method FROM elimfilters_catalog WHERE sku='EL81016')),
  burst_pressure_psi = COALESCE(burst_pressure_psi, (SELECT burst_pressure_psi FROM elimfilters_catalog WHERE sku='EL81016')),
  collapse_pressure_psi = COALESCE(collapse_pressure_psi, (SELECT collapse_pressure_psi FROM elimfilters_catalog WHERE sku='EL81016')),
  installation_type = COALESCE(installation_type, (SELECT installation_type FROM elimfilters_catalog WHERE sku='EL81016')),
  alternative_codes = '["EL81016"]'::jsonb
WHERE sku='EL82100';
```

## Cambios
- ✅ EL82100 ahora tiene todos los campos técnicos completos
- ✅ EL81016 está marcado como alternativa en `alternative_codes`
- ✅ Búsqueda por LF3620 retorna EL82100 (principal con datos completos)
- ✅ Los códigos OEM se mantienen en ambos productos
