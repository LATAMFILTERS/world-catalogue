# Nodal Center — Canonical Knowledge Promotion Policy

## Purpose

Structured knowledge created by HERMES enters Nodal Center as `candidate`. A candidate is internal evidence-backed engineering work, not canonical ELIMFILTERS knowledge and not public Knowledge Center content.

Promotion is always explicit and note-by-note. Bulk promotion is prohibited.

## Promotion gate

A candidate may become `approved` canonical ELIMFILTERS knowledge only when all of the following are true:

1. The note remains source-neutral: no external source brand, source URL, private source ID or copied source text is present.
2. The domain, industry and system classification is valid. Non-shared knowledge may use only the five official ELIMFILTERS systems.
3. At least one neutral `EVID-*` evidence reference exists.
4. Scope review explicitly confirms system registry, technical scope, source neutrality, absence of proprietary external claims and public-language suitability.
5. Any ELIMFILTERS technology relationship has been resolved from `probable` to `confirmed` before canonical approval.
6. Any candidate application relationship has been explicitly resolved as `verified`, `rejected` or `not_applicable` in the review record.
7. Every metric used by the note is individually approved in the technical validation ledger.
8. Every technical relationship used by the note is individually approved in the technical validation ledger.
9. Every procedure used by the note is individually approved in the technical validation ledger.
10. The final reviewer and review timestamp are recorded and `review_status` is `approved`.
11. The promotion baseline remains internally consistent.
12. The universal public knowledge gateway remains the final public-output guard after canonical promotion.

## Metrics

The initial LD Automotive package captured 47 metric occurrences. Five are exact duplicate extractions within the same evidence context. Governance therefore retains all 47 occurrences for traceability while presenting 42 unique source/evidence metric claims for review. Those 42 claims represent 29 unique technical values.

A metric review requires an approved validation method. Valid methods are: cross-source validation, standard reference, internal engineering calculation, controlled test, registry validation or engineering review. Cross-source validation requires at least two neutral evidence IDs.

## Technical relationships

The package contains 32 unique normalized technical relationships. Each relationship receives its own ledger decision. A relationship cannot inherit approval merely because it appears in several notes or in Shared Engineering.

## Procedures

The package contains 11 procedures. Each procedure must be reviewed independently before any note that uses it can pass the promotion gate.

## Authority boundaries

HERMES researches, structures and enriches candidates. HERMES cannot approve or publish canonical knowledge. Nodal Center review creates canonical knowledge authority only after the promotion gate passes. PostgreSQL remains the sole SKU authority. Canonical promotion never writes SKUs, applications, cross references, pgvector records or catalog data.

Canonical promotion also does not automatically publish to the Knowledge Center. Knowledge Center publication remains a separate governed step.
