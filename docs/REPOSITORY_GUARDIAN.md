# ELIMFILTERS Repository Guardian

This document defines the rules that keep the repository stable after the Knowledge Center expansion and the static-export merge conflicts.

## Why this exists

The repository previously broke because multiple branches committed generated output at the same time. Git then had to merge hundreds of generated HTML, TXT, sitemap, citation API, and Next.js hash files.

Generated files should be produced by the build/deploy pipeline, not manually merged between feature branches.

## Protected workflow

Use this flow for all work:

```text
feature/* or fix/*
  -> Pull Request
  -> Repository Guardian checks
  -> Review
  -> merge to main
```

Do not push directly to `main`.

## Files that should not be changed in normal PRs

The Repository Guardian blocks changes to these generated outputs:

```text
frontend/out/**
frontend/public/api/citation/**
elimfilters-vault/00-meta/CITATION_INDEX.json
frontend/src/lib/jsonld-constants.generated.ts
```

These files are generated by:

```bash
npm run build
```

If generated output needs to be refreshed, do it in a dedicated automation/deploy process, not mixed into feature PRs.

## Required checks

Every PR to `main` should pass:

- Repository Guardian / Block generated artifact changes
- Repository Guardian / Build and type validation
- Repository Guardian / Conflict marker check

## Recommended GitHub branch protection for `main`

In GitHub:

```text
Settings -> Branches -> Add branch protection rule -> main
```

Enable:

- Require a pull request before merging
- Require status checks to pass before merging
- Require branches to be up to date before merging
- Require conversation resolution before merging
- Do not allow bypassing the above settings
- Restrict who can push to matching branches, if appropriate

Use these required status checks:

```text
Repository Guardian / Block generated artifact changes
Repository Guardian / Build and type validation
Repository Guardian / Conflict marker check
```

## Emergency recovery

If a local branch diverges because generated files were committed in multiple places:

```bash
git fetch origin
git switch main
git reset --hard origin/main
npm run build
```

Create a backup branch before any destructive reset:

```bash
git switch -c backup/<description>
git push -u origin backup/<description>
```

## Future improvement

The best long-term fix is to remove generated files from version control entirely. That requires a separate cleanup PR because these paths are currently tracked.
