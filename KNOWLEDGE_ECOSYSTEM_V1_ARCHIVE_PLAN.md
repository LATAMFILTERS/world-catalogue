## Purpose of This Document

This document defines the complete archive package for the ELIMFILTERS Knowledge Ecosystem V1. It specifies what to preserve, how to organise it, and what format each item should take for long-term storage, external backup, PDF export, and offline USB preservation.

The archive is not the repository. The repository is a live development environment. The archive is a point-in-time preservation of Version 1 in a format that can be retrieved, understood, and redeployed without access to the live repository or any development toolchain.

---

## Archive Scope

**What the archive covers:**
- All knowledge graph assets (vault notes, compiled indexes, traversal maps)
- All pipeline scripts (four core build scripts)
- All compiled API output (195 static JSON files)
- All milestone and review documents (reports, plans, declarations)
- All final closure documents
- A standalone README sufficient to reconstruct the ecosystem from scratch

**What the archive does not cover:**
- The full Next.js frontend source (too large for offline preservation; available in git)
- The `unified-data.ts` product catalogue (separate system; archive separately)
- Legacy pre-Phase 3 utility scripts (not part of the knowledge ecosystem)
- `frontend/out/` build artifacts (regenerated by `npm run build`; not archival)
- Node modules and build caches

## 7. Part Search Documentation

### Map file

`elimfilters-vault/00-meta/PART_SEARCH_MAP.json` — the primary Part Search integration asset.

**Key fields for documentation:**

```
meta.path_count:            99
meta.valid_path_count:      97
meta.product_family_count:  5
meta.coverage_summary:
  problems_with_complete_paths:    5/5
  industries_with_complete_paths:  11/11
  technologies_with_product_families: 5/7
  product_families_reachable:      5/5
```

**Three path types defined:**
- Type A: Problem → ContaminationMode → Technology → ProductFamily (12 valid)
- Type B: Industry → Problem → ContaminationMode → Technology → ProductFamily (80 valid)
- Type C: Technology → ProductFamily (direct, 5 valid / 2 invalid)

### Integration reference

To implement `citations=true` in Part Search, the integration point is:
```
GET /api/citation/path/by-entry/[INDUSTRY_KEY].json
```
This returns all valid traversal paths for a given industry, with full CitationRecord detail at each step. No additional backend infrastructure required.
